## Recognition code and weights

- **Partsong**, Paul Fremantle and contributors: https://github.com/pzfreo/partsong, revision `61e9aa3c19893f09a07fe8decbcafeaf735988d3`, AGPL-3.0. A subset is preserved in `vendor/partsong`, including copyright/license notices and upstream build/download scripts. Runtime reuse is limited to OMR worker/WASM and photo orientation. modScore does not execute Partsong's app, relay, analytics or sharing code. The modScore fork modifies the page reader for lower G/C clefs and image-verified recovery of clipped staff extents and barline review signals, and modifies the worker to report decoder truncation and geometric repairs. Additional worker patches are generated by `scripts/prepare-assets.mjs`: one WASM CPU thread and resource instrumentation. The changed SIMD and relaxed-SIMD binaries were rebuilt with Rust 1.96 for wasm32; corresponding source and build instructions are included. Optional thread variants are retained upstream artifacts and are not selected by the app’s one-thread path. The app uses separate layout/recognition passes to release the segmentation session before encoding symbols.
- **homr-rs**, Paul Fremantle and contributors: https://github.com/pzfreo/homr-rs, revision `f6309104e3582bae8df22669f0325e7fd1a7ab32`, AGPL-3.0-only. Corresponding source is vendored, with Cargo locks and build instructions. Its upstream README calls the port experimental. Do not substitute upstream benchmark claims for modScore device testing.
- **homr**, Christian Liebhardt and contributors: https://github.com/liebharc/homr. License FAQ inspected at revision `94324aee60ea955c7fe37c287e29199b5061544a`; code and published model weights are AGPL-3.0. The pipeline descends from oemer and Polyphonic-TrOMR. The native Python implementation was researched but is not required by the PWA. See `docs/licenses/homr-LICENSE_FAQ.md`.

### Training-data provenance caveat

homr's maintainers state that AGPL cannot grant more rights than the training data allows. Whether training-data terms carry through to weights remains unresolved. Their November 2026 FAQ lists:

| Data | Reported terms / provenance |
| --- | --- |
| DeepScoresV2 | CC BY 4.0; https://zenodo.org/records/4012193 |
| OpenScore Lieder and StringQuartets | CC0; https://github.com/OpenScore/Lieder and https://github.com/OpenScore/StringQuartets |
| GrandStaff | No license stated at the original grfia download source; MIT metadata on https://huggingface.co/datasets/PRAIG/grandstaff |
| PDMX `no_license_conflict` subset | CC BY 4.0 for the dataset; public-domain status inferred from score metadata; https://zenodo.org/records/15571083 |

These are upstream statements, not an independent legal clearance of every underlying score. Model redistribution must preserve this caveat and all attribution. This repository does not claim that the uncertainty has been resolved or that a commercial deployment has been legally cleared. No private scores or datasets are included.

## Instrument samples

FluidR3 GM by **Frank Wen**, converted for MIDI.js by **Benjamin Gleitzman** and contributors: https://github.com/gleitz/midi-js-soundfonts, pinned revision `044fab8e1456bfafc5776e86dfd6bb8697149aef`. Its README identifies FluidR3 samples as **Creative Commons Attribution 3.0 United States**: https://creativecommons.org/licenses/by/3.0/us/. Attribution must accompany redistribution. The repository's software/conversion code is MIT, copyright 2012 Benjamin Gleitzman; that MIT license does **not** replace the samples' CC BY terms.

modScore converts the acoustic grand piano MP3 bank to a data-only JSON object. Optional banks are fetched from the pinned raw GitHub revision and parsed as data; downloaded JavaScript is never evaluated. One active bank is decoded at a time. Original notes outside the recorded sample range use rate-shifted samples at their true pitch. GM channel 10 currently uses modScore's original synthesized percussion approximations, not FluidR3 percussion samples.
