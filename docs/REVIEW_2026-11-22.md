# 0.2 recognition and lifecycle review — 2026-11-22

The user's provided original image was processed locally using the pinned CPU OMR pipeline. It produced nine measures and 74 sustained events. This is a measured output count, not an accuracy score. Neither the copyrighted input screenshot nor its recognized XML/preview is distributed with the application's test corpus or source archive; private diagnostic artifacts remain under the excluded `omr-validation/user/` directory.

Visual and XML inspection found a concrete error in measure 3: the E4 tie is encoded, but the C4 chord-tone tie is absent. C4 is consequently attacked again at beat 10 instead of being sustained from beat 8.5. Auto-beaming cannot correct this semantic error. The editor now provides explicit **Tie to next note** / **Remove tie** operations, constrained to contiguous same-pitch/staff/voice events. The application does not silently infer missing ties from proximity.

The original's beamed eighth-note groups were rendered as separate flags in the previous version. OSMD auto-beaming now reconstructs engraving without modifying XML playback duration. Systems use three measures on larger viewports and two on narrow viewports, with redundant title/part labels omitted. A Compare tab displays the source image alongside reconstructed notation; mobile stacks the views. Structural timing auditing reports encoded durations and ties, explicitly without claiming image-recognition confidence. A full measure can still contain an incorrect pitch or omitted tie.

The phrase “Slowly, steady tempo” is not a numeric metronome mark. OMR does not recover it reliably, and this release does not assign a guessed BPM to it. The review editor can save a user-entered numeric BPM and optional tempo instruction into the MusicXML, retaining the correction in library backups and exports.

Update handling is separated into `src/updates.ts`. A controller owns one banner and cleans its listeners. It suppresses first-install prompts, offers Update/Later for a waiting version, saves the current project before activation, and reloads only after an explicitly requested update. A waiting update itself is expected PWA behavior, while duplicate banners/listeners were a defect in the old implementation.

A missing local model directory was also found during validation. Previously Vite's HTML fallback was treated as an incomplete model download and retried. The generated worker now detects an HTML response and reports a missing-host-asset error immediately. Downloaded model files were restored and verified against the existing SHA-256 lock.

The standard `mobile-web-app-capable` metadata is supplied alongside the iOS-specific metadata. `contentscript.js` / ObjectMultiplex / app-init-liveness messages match the MetaMask extension's documented issue https://github.com/MetaMask/metamask-extension/issues/43090 and its service-worker source. Those files are not shipped by modScore. A fresh Chrome profile used for the revised-score and Compare views reported no page errors. The user's own extension URL/stack would be needed to identify their exact installed extension conclusively; no extension settings were changed or warnings suppressed.

Validation: the desktop/mobile suite passed 33 tests with one explicit mobile multipage skip; after adding tie correction, all four focused review/update/tie tests passed. Tests cover saved numeric tempo, repeated worker events with only one banner, save-before-activation ordering, first-install suppression, and tie join/remove round trips on original CC0 notation. Existing CPU OMR integration, PDF import, audio/key synchronization, persistence and MIDI round-trip checks passed in the suite.

Next priorities: a larger licensed multivoice piano image corpus with per-note/tie error metrics; localized note/staff crop retries with user-visible alternatives; explicit dynamics/pedal/articulation support in the shared event timeline; and physical iPhone XS memory/latency testing. OCR for tempo prose, lyrics and chord symbols requires a separately validated local text pipeline. Cosmetic engraving repairs must remain separate from semantic corrections.

Release verification: the missing-model HTML failure test passed in 454 ms, without waiting for eight retry cycles. The production 0.2 build passed CPU OMR, network-disconnected shell reload, sampled playback, non-silent WAV export and recognition of a new image offline. Cache identity and actual run date are recorded in `validation/revision02-offline.json`. Physical iPhone testing remains unperformed.
